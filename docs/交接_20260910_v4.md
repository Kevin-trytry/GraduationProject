## 一、★ 今天的關鍵實驗：只改距離，準確率翻倍

兩場測試相隔 6 分鐘。**同一顆模型、同一份韌體、同一個環境、同一個人。唯一變因是手離鏡頭的距離。**

| | 19:46 手貼近 | **19:52 手退後** |
|---|---|---|
| **逐幀核對準確率** | **3 / 14 = 21%** | **8 / 16 = 50%** |
| 手的垂直跨幅（膚色遮罩量測） | 84% 畫面高 | **73%** |
| 手的水平跨幅 | 37% | **27%** |
| 最大類別佔比 | cls4 **42%** | cls2 27% |
| 出現的類別數 | 9 | **10** |
| 滿版框（>85% 畫面） | 39% | **22%** |
| 平均信心度 | 47% | **40%** |
| ≥70% 佔比 | 22% | **6%** |

手的線性尺寸只縮小約 **1.25 倍**，準確率就從 21% 變成 50%。

### 貼近時發生的事：偵測塌陷

19:47:07–19:47:36 有一段 **95 幀連續 cls4**，平均 68%、中位 74%、最高 94%。
那 30 秒我實際比的是 **5 → 7 → 5**，三個不同手勢。

cls4 的框中位數是 **314×226**（畫面 320×240，佔 93%），而正確的那些偵測框只佔 59~78%。

> **模型無法定位時，就吐一個滿版框配上 cls4。**
> 全場 67 筆 ≥70% 的偵測有 62 筆是 cls4，幾乎全錯。

退後之後這個退化模式消失，cls4 佔比從 42% 掉到 13%。

## 二、★ 我要收回 v3 的一個論證

v3 寫：「Layout A 平均信心度 42%，跟 Layout B 一樣，所以 Layout A 沒有幫助。」

**這個比法無效。** 今天證實：**信心度更低的那一場，準確率是兩倍。**

因為模型崩潰時會產生「假的高信心度」（滿版框 + 單一類別），所以平均信心度越高反而可能代表越糟。

三個延伸結論：

1. **調高 score threshold 沒用** —— 拉高只會保留錯的
2. **多幀投票沒用，甚至有害** —— 只會把錯誤鎖得更穩
3. **Layout A 到底有沒有幫助，目前仍未定論** —— 需要用新的評估方式重測

**Layout A 你已經做對了，先不用動。** 等尺度問題處理完再回頭比。

## 三、★ 請你做的事（依優先序）

### 3.1 加 scale augmentation（最高優先，成本最低）

```python
model.train(
    data='dataset.yaml',
    imgsz=192,
    scale=0.7,        # ← 關鍵：隨機縮放 ±70%
    mosaic=1.0,       # 保持開啟，會自然產生多尺度
    ...
)
```

`scale` 若目前是預設 0.5 也請確認實際有生效（有些設定組合會被 `mosaic=0` 或 `rect=True` 影響）。

**這是根治方案。** 讓模型對手的大小不敏感，板子上手放多遠都能認。

### 3.2 統計訓練集標註框的面積分布（成本很低，但能直接證實推測）

```python
import glob, numpy as np
areas = []
for f in glob.glob('labels/**/*.txt', recursive=True):
    for line in open(f):
        p = line.split()
        if len(p) >= 5:
            areas.append(float(p[3]) * float(p[4]))   # w * h（已正規化）
a = np.array(areas)
print(f"n={len(a)}")
for q in (5, 25, 50, 75, 95):
    print(f"  P{q} = {np.percentile(a, q)*100:.1f}%")
```

**判讀：**

| 結果 | 意義 |
|---|---|
| P5~P95 落在很窄的區間（例如 20~35%） | **推測成立** → 3.1 必做 |
| 分布很寬（5%~80%） | 尺度不是問題，另尋原因 |

板子上手貼近時，框面積是 **93%**；退後時是 **59~78%**。可以直接跟上面的分布對照。

### 3.3 逐類別 mAP（仍然要，v3 就提過）

```python
r = model.val(data='dataset.yaml', imgsz=192, split='val', verbose=True)
```

**請給每一類的 P / R / mAP50 / mAP50-95，不要只給平均值。** 平均值會被表現好的類別掩蓋。

### 3.4 validation 改 group split（仍然要）

`data handling/train_yolo.py` 目前是對全部影像 i.i.d. 隨機洗牌。資料是連拍影格，同一秒內幾乎一樣的相鄰影格會同時落在 train 和 val。

```python
from collections import defaultdict
groups = defaultdict(list)
for img, lbl in pairs:
    key = img.stem.rsplit('_', 1)[0]     # 依實際命名規則調整
    groups[key].append((img, lbl))

keys = list(groups); random.shuffle(keys)
n = len(keys)
train_keys = keys[:int(n*0.8)]
val_keys   = keys[int(n*0.8):int(n*0.9)]
test_keys  = keys[int(n*0.9):]
```

**改完重新評估。如果 mAP 掉很多，那才是真實的泛化能力。**

## 五、★ 評估方式（我們兩邊都要照做）

今天的教訓是：**用錯指標會得到相反的結論。**

**不要用**：類別出現筆數、平均信心度、最高信心度、>70% 佔比。這四個今天都被證實會誤導。

**要用**：

```
依序比 0 → 1 → 2 → ... → 9 → B
每個手勢停 8~10 秒，中間手放下 2 秒當分隔
手離鏡頭約 30 cm，佔畫面約一半
一律 --no-vote
```

跑完約 2 分鐘，逐幀核對就能算出真實準確率與混淆矩陣。
