### 為什麼這件事危險

這是典型的 train / deploy 不一致，而且**在 val mAP 上完全看不出來** ——
val 也被銳化了，所以驗證分數會很漂亮，實機卻可能更差。

板子的畫面本來就偏軟：

```
感測器 320x240（本身就不銳利）
  → 韌體 center-crop 取中央 240x240
  → 雙線性縮放到 192x192（2-tap，無抗鋸齒預濾波，又糊一層）
  → 送進模型
```

模型若學會依賴銳利的邊緣，到板子上就找不到那些邊緣。
**這一項有可能把 `scale=0.7` 帶來的好處吃掉。**

## 🔵 更正：`fliplr` 我先前講錯了

v5 我寫「`fliplr` 一定要關掉，左右手互換會讓語意改變」。你這次是 `fliplr=0.5`（預設值，沒關）。

**我那個建議是錯的，你沒改是對的。**

0~9 和 B 這 11 類，鏡像之後都還是同一個手勢 ——
