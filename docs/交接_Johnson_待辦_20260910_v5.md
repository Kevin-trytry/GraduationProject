### 怎麼判讀

**有 scale augmentation 的資料集，類別內 P90/P10 通常在 3~10 倍。這裡全部都是 1.1~1.8 倍。**

意思是：模型看過的每一張「5」，手的大小都幾乎一樣。它沒有機會學到「不管手多大，五根手指就是 5」。

### 這直接解釋了實機上的三個現象

**① 為什麼 cls5 幾乎完全讀不到**

訓練時 cls5 的框寬中位數是 **97%** —— 手橫跨整張圖。
Kevin 在板子上量到的手，水平跨幅只有 **27~37%** 畫面寬。

**差了快三倍。模型沒看過那麼小的手。**

**② 為什麼失敗的剛好是 4/5/6/7/8/9**

```
會的：  0(寬60%) 1(53%) 2(63%) 3(65%)
不會的：4(80%) 5(97%) 6(95%) 7(84%) 8(95%) 9(92%)
```

界線落在框寬 65% 與 80% 之間，跟「拇指」「手指數量」的分類無關 —— **是尺度**。

**③ 為什麼同一顆模型每一場測出來的結果都不一樣**

2026-09-10 同一顆模型、同一份韌體、30 分鐘內四場，主導類別一直換：

| session | 主導類別 | cls0 | cls5 | cls6 |
|---|---|---|---|---|
| 19:46 | cls4 42% | 16 | 4 | 0 |
| 19:52 | cls2 27% | 10 | 1 | **13** |
| 20:02 | cls4 32% | **29** | **0** | 3 |
| 20:14 | cls2 35% | **1** | 3 | 2 |

**唯一的變因是手放的位置和距離。** 這也代表「哪一類出現最多」不是資料比例造成的 —— 不要為了平衡而去刪某一類的樣本，那只會讓落點搬家。

## 三、★ 任務 2：加 augmentation 重訓

```python
model.train(
    data='data.yaml',
    imgsz=192,
    epochs=...,

    # ── 關鍵三行 ──────────────────────────────
    scale=0.7,        # 隨機縮放 ±70%，讓模型看過各種大小的手
    translate=0.2,    # 隨機平移 ±20%，手不一定在正中央
    mosaic=1.0,       # 四張拼一張，會自然產生多尺度
    # ─────────────────────────────────────────

    fliplr=0.5,       # 保持預設開啟（見下方更正）
    degrees=10,       # 小幅旋轉，手不會永遠是正的
)
```

### ⚠️ 更正（09-11）：`fliplr` 不要關

本文初版寫「`fliplr` 一定要關掉」。**那個建議是錯的。**

0~9 和 B 這 11 類鏡像之後都還是同一個手勢 —— 右手比的 7（拇指+食指）
鏡像就是左手比的 7，仍然是 7。沒有任何兩類會因鏡像撞在一起。
開著反而讓模型同時吃左右手，demo 時用哪隻手都行。**請保持 `fliplr=0.5`。**

### 要注意的一個坑

**確認 `scale` 真的生效。** `rect=True` 或 `mosaic=0` 會讓部分 augmentation 失效。
訓練開始時 ultralytics 會印出實際採用的超參數，對一下。

重訓完再跑一次 `check_label_scale.py` 沒有意義（它量的是標註，不是 augmentation）—— 改看任務 3 的逐類別 mAP。

## 五、任務 4：validation 改 group split

`train_yolo.py` 目前：

```python
random.shuffle(pairs)      # ← 對「全部影像」i.i.d. 隨機洗牌
```

資料是連拍影格。隨機切分會讓同一秒內幾乎一模一樣的相鄰影格同時落在 train 和 val，
**mAP 衡量的是「有沒有記住」，不是「能不能泛化」。**

```python
from collections import defaultdict
groups = defaultdict(list)
for img, lbl in pairs:
    key = img.stem.split('.mov')[0]      # 依實際命名調整，目的是「同一段影片不跨 train/val」
    groups[key].append((img, lbl))

keys = list(groups); random.shuffle(keys)
n = len(keys)
train_keys = keys[:int(n*0.8)]
val_keys   = keys[int(n*0.8):int(n*0.9)]
test_keys  = keys[int(n*0.9):]
```

改完重新評估。**mAP 掉很多是正常的，那才是真實數字。**
