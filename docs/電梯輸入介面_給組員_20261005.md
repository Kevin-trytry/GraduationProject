## 〇、一句話

執行 `grove_vision_capture.py --elevator --elev-http 8765`，
你的程式去 `http://127.0.0.1:8765/` 拿狀態和事件，不用碰串列埠、不用碰模型。

---

## 一、使用者怎麼操作

```
比出數字，維持 3 秒          →  鎖定第 1 位
手移開畫面 0.8 秒            →  分隔
比出數字，維持 3 秒          →  鎖定第 2 位
手移開畫面 0.8 秒            →  進入確認
3 秒內不要舉手               →  送出樓層
   （確認期間舉手 = 取消）
```

**為什麼要停 3 秒**：手勢剛比出來和準備放下的那零點幾秒，手指還在移動，是誤判最集中的時段。
系統只取中間 2 秒（約 8~10 幀）做多數決，一致度不到 70% 就拒絕。

**為什麼要「手移開」當分隔**：不然「11 樓」會被看成一個連續的 1，分不出是一位還是兩位。

---

## 二、樓層編碼

| 第 1 位 | 第 2 位 | 結果 |
|---|---|---|
| `B` | `1`~`9` | 地下 n 樓 → `"B1"` ~ `"B9"` |
| `0` | `1`~`9` | `"1F"` ~ `"9F"` |
| `1`~`9` | `0`~`9` | `"10F"` ~ `"99F"` |

**不合法（會發 `floor_invalid`，不送出）**：`00`、`B0`、第 2 位比 `B`、超過 `--elev-max-floor`。

## 三、三種接法，挑一種就好

| 管道 | 怎麼拿 | 適合 |
|---|---|---|
| **HTTP** | `--elev-http 8765`，然後 `fetch()` | **HTML 模擬器（建議）** |
| **stdout** | 每個事件一行 `[ELEV] {json}` | Python 用 `subprocess` 接管道 |
| **JSONL** | `captures/session_*/elevator_events.jsonl` | 事後重播、對帳 |

三個可以同時開，互不影響。

## 四、HTTP 介面

只綁 `127.0.0.1`，已開 CORS，純標準函式庫，不需要安裝任何套件。

### `GET /state` — 現在的狀態（輪詢用，建議 100ms）

```json
{
  "state": "holding",
  "digits": ["1"],
  "pos": 2,
  "holding": "2",
  "hold_elapsed": 1.4,
  "hold_need": 3.0,
  "hold_ratio": 0.47,
  "pending_floor": null
}
```

`state` 有四種，**UI 應該要讓使用者看得出現在在哪一種**：

| state | 意思 | 畫面該顯示 |
|---|---|---|
| `idle` | 等待比手勢 | 「請比出第 N 位數字」 |
| `holding` | 正在累積停留時間 | **進度環**，用 `hold_ratio`（0~1） |
| `gapwait` | 數字鎖定了，等手移開 | `hand_present` 為 true 時提示「把手移開」；false 時用 `gap_ratio` 畫進度 |
| `confirm` | 兩位齊了，等確認 | 「即將前往 X，舉手取消」，倒數用 `confirm_remain` |

### `GET /events?since=N` — 事件串流

```json
{ "next": 12, "events": [ { "t": 3.01, "event": "digit_locked", ... } ] }
```

把回傳的 `next` 當作下一次的 `since`，就不會漏也不會重複。第一次傳 `since=0`。

### `GET /health`

```json
{ "ok": true }
```

## 五、事件清單

| event | 什麼時候 | 重要欄位 |
|---|---|---|
| `hold_started` | 開始比一個數字 | `pos` |
| `digit_locked` | 一位數字鎖定 | `pos`, `value`, `agree`, `conf_median`, `frames`, `spread` |
| `digit_rejected` | 停留時間到但品質不夠 | `reason`, `detail`（中文說明）, `top`, `spread` |
| `ready_for_next` | 分隔完成，可以輸入下一位 | `pos` |
| **`floor_pending`** | **兩位齊了，開始確認倒數** | `floor`, `value`, `confirm_sec` |
| **`floor_dispatched`** | **確認通過，這就是最終樓層** | `floor`, `value`, `digits` |
| `floor_invalid` | 兩位組不出合法樓層 | `digits`, `reason` |
| `cancelled` | 確認期間舉手 | `reason`, `floor` |
| `reset` | 逾時或流程重置 | `reason` |

**你真正需要反應的只有 `floor_dispatched`。** 其他是給 UI 做回饋用的。

`digit_rejected` 的 `detail` 是寫好的中文句子，可以直接顯示給使用者，例如：

```
8 幀裡只有 5 幀是 5（62%），手勢不夠穩定
```

`floor_dispatched` 的 `value` 已經拆好了，不用自己 parse 字串：

```json
{ "kind": "above",    "level": 12, "number":  12 }   // 12F
{ "kind": "basement", "level":  1, "number":  -1 }   // B1
```

## 六、最小可用的 HTML 接法

```html
<script>
let since = 0;

async function poll() {
  // 1) 即時狀態 → 畫進度環
  const s = await (await fetch('http://127.0.0.1:8765/state')).json();
  render(s);

  // 2) 事件 → 觸發動作
  const r = await (await fetch(`http://127.0.0.1:8765/events?since=${since}`)).json();
  since = r.next;
  for (const e of r.events) {
    if (e.event === 'floor_dispatched') goToFloor(e.value);   // ← 真正要做的事
    if (e.event === 'cancelled')        showToast('已取消');
    if (e.event === 'digit_rejected')   showToast(e.detail);
  }
}
setInterval(poll, 100);
</script>
```

> ⚠️ 用 `file://` 直接開 HTML 時，有些瀏覽器會擋住對 `127.0.0.1` 的 fetch。
> 開一個本機伺服器就好：`python -m http.server 8080`，然後開 `http://localhost:8080/`。

Python 端的話：

```python
import json, subprocess
p = subprocess.Popen(['python', 'grove_vision_capture.py', '--elevator'],
                     stdout=subprocess.PIPE, text=True, encoding='utf-8')
for line in p.stdout:
    if line.startswith('[ELEV] '):
        e = json.loads(line[7:])
        if e['event'] == 'floor_dispatched':
            go_to_floor(e['value'])
```

## 七、參數（都可以從命令列調）

```bash
python grove_vision_capture.py --elevator --elev-http 8765 --no-vote
```

| 參數 | 預設 | 說明 |
|---|---|---|
| `--elev-dwell` | 3.0 | 一個數字要維持幾秒 |
| `--elev-trim` | 0.5 | 停留視窗掐頭去尾各幾秒 |
| `--elev-gap` | 0.8 | 兩位之間手要移開幾秒 |
| `--elev-confirm` | 3.0 | 確認倒數 |
| `--elev-agree` | 0.70 | 多數決最低一致比例 |
| `--elev-conf-min` | 30 | 勝出類別的信心度中位數下限（%） |
| `--elev-min-frames` | 5 | 停留視窗最少幀數 |
| `--elev-max-floor` | 99 | 最高樓層 |

**不加 `--elevator` 的話，腳本的行為跟以前完全一樣**，不影響既有的測試流程。

## 八、已知限制（請一起知道）

1. **`5` 和 `9` 目前不穩。**
   09-30 實測：`9` 兩場各只偵測到 2 筆和 1 筆、信心度 35~37%；`5` 的信心度在兩場之間從 78% 掉到 59%。
   以預設的 `--elev-conf-min 30` 來說，`9` 很可能鎖不住（會一直 `digit_rejected`）。
   **這是模型的問題，不是這套邏輯的問題**，正在訓練端處理。
   → UI 要能顯示 `digit_rejected`，不然使用者只會覺得「比半天沒反應」。

2. **幀率下限約 2.5 fps。**
   實測是 3.5~4.6 fps，中間 2 秒視窗拿得到 8~10 幀。掉到 1.7 fps 以下，
   視窗幀數不足 5 會直接拒絕（寧可不動，也不要猜錯樓層）。

3. **手要在畫面中央。**
   韌體用 center-crop，只看畫面中央 240×240 的範圍，框外完全看不到。
   加 `--crop-guide` 可以在預覽上看到這個範圍。

4. **「手移開」必須真的沒有偵測框。**
   如果背景會產生誤偵測，分隔就永遠不會完成。遇到的話調高 `--threshold`。

5. **目前沒有專用的取消手勢。**
   `B` 被拿去當地下室了。取消的方式是：確認倒數期間舉手。
   另外閒置 15 秒會自動重置。

## 九、怎麼在沒有板子的情況下驗證

```bash
# 合成情境測試（16 項）
python test_elevator_input.py

# 拿既有的測試資料回放
python elevator_replay.py captures/session_20260930_191643/detections_log.csv
python elevator_replay.py <csv> --elev-agree 0.6 --verbose
```

回放是調參數最快的方法 —— 不用接板子、不用比手勢，改個數字重跑就看得到結果。
