## 四、★ 請你做的測試（分辨「訓練」還是「量化」）

剩下的問題只有兩種可能：

- **A. 96 那次訓練出來的權重本身不行**
- **B. `best.pt` 是好的，但 export → int8 量化 → Vela 這一段把模型弄壞了**

### 測試方法

```python
from ultralytics import YOLO
m = YOLO('best.pt')                      # 96 那版
r = m.predict('model_input_96x96.png', imgsz=96, conf=0.01, verbose=True)
print(r[0].boxes)
```

`conf=0.01` 刻意調到極低，這樣就算信心度只有 2% 也看得到。

### 判讀

| 結果 | 結論 | 下一步 |
|---|---|---|
| **偵測到 V 手勢、信心度 > 0.5** | 權重是好的 → **問題在量化 / 匯出** | 查 `export_full_int8.py`：校正資料（見第五節）、`representative_dataset`、Vela 參數 |
| **也偵測不到，或只有幾 %** | **權重本身不行** | 見第六節（驗證集切分） |

## 五、一個已知但尚未驗證因果的缺陷：量化校正資料只有 cls0

你那邊已經找到並修正了：`export_full_int8.py` 的 `representative_dataset()` 用 `rglob` 遞迴走訪再 `[:100]`，而 `0` 資料夾有 341 張，所以**100 張校正圖片全部是 cls0（拳頭）**。

這個缺陷值得特別注意，因為它對兩種 Layout 的傷害程度不同：

| | Layout A（192 那顆） | Layout B（96 那顆） |
|---|---|---|
| bbox 輸出 | 獨立 scale `1.281`（已解碼像素值） | 與 class **共用** scale `0.169` |
| class 輸出 | 獨立 scale `1/256`（已過 sigmoid，0~1） | 與 bbox **共用** scale `0.169`（raw logit） |
| 校正偏斜的影響 | 分散到兩個獨立 scale，各自仍能貼合自己的分布 | **一個 scale 要同時服務兩種完全不同量級的張量** |

**Layout B 對校正資料的品質敏感得多。** 這可以解釋為什麼同樣的校正缺陷下，192（Layout A）還能跑到 90%，而 96（Layout B）掛掉。

> 不過要誠實說：這是**合理推測，還沒有直接證據**。第四節那個測試才能確認。

### 順帶建議：改用 Layout A

`Pileline_3_firmware.md` §2.2 有寫，**韌體兩種格式都支援、自動偵測、換模型不用改 code 也不用重編**。

若 export 端加上完整的 split-output patch（DFL 解碼 + sigmoid 在匯出時就做掉），產出 Layout A：

- class 量化解析度從每階 **4.2 個百分點** 變成 **0.39 個百分點**（差約 11 倍）
- bbox 與 class 各自有貼合自己分布的 scale，不再互相拖累
- 順便省掉韌體端每幀的 softmax 運算

**192 那顆能跑到 90%，本身就是 Layout A 可行的證明。**

## 六、關於 mAP 0.982 —— 這個數字可能不代表泛化能力

`data handling/train_yolo.py` 的切分方式：

```python
def split_dataset(pairs, train_ratio=0.80, val_ratio=0.10, seed=42):
    random.seed(seed)
    random.shuffle(pairs)      # ← 對「全部影像」做 i.i.d. 隨機洗牌
```

`collect_pairs()` 把 11 個資料夾底下的影像攤平成一個 list，再整包洗牌切 80/10/10。

資料集約 1226 張，是**同一批連拍**的影格。隨機切分會讓**同一秒內、幾乎一模一樣的相鄰影格同時落在 train 和 val**。模型在驗證集上看到的，其實是它訓練時已經記住的畫面。

**這種切分下的 mAP 主要衡量「有沒有記住」，不是「能不能泛化」。**

### 建議：改用 group split

以拍攝場次／檔名前綴／時間戳為單位切分，確保同一段連拍只出現在 train 或 val 其中一邊：

```python
from collections import defaultdict
groups = defaultdict(list)
for img, lbl in pairs:
    key = img.stem.rsplit('_', 1)[0]     # 依實際命名規則調整
    groups[key].append((img, lbl))

keys = list(groups); random.shuffle(keys)
n = len(keys)
train_keys = keys[:int(n*0.8)]
val_keys   = keys[int(n*0.8):int(n*0.9)]
test_keys  = keys[int(n*0.9):]
```

改完重新評估一次。如果 mAP 掉很多，那就找到真正的問題了。

## 九、韌體端目前狀態（供參考，不需要你處理）

| 項目 | 說明 |
|---|---|
| `cv_yolov8n_ob_init()` 的 `return false` | Himax 原版 bug：`false` = 0 = 成功碼，且呼叫端沒接回傳值。已改 `-1` + `[FATAL]` 訊息 |
| anchor 對帳的靜默 return | 原本失敗時完全不出聲，已改成大聲報錯 |
| 大框面積門檻 | `0.80f → 0.95f`（依實測面積分布 P50=77%、正常框最大 79.7% 調整） |
| Layout A bbox 歸一化自動判斷 | 原廠 COCO 模型是歸一化 0~1、我們的是像素值，已能自動分辨 |
| 診斷輸出 | `[INPUT]`（輸入健檢）、`[POST]`（各關卡存活數）、`[CLS-DBG]`（11 類分數）、`[DUMP]`（輸入張量傾印） |
| `switch_input_size.py` | 一個指令切換 96/192 全鏈路（韌體 define + 模型 + 兩支腳本） |
